# 下級生 (새턴 JP 3장) — 초기 조사 (2026-10-23)

## 디스크

- 3장 모두 Track1 MODE1/2352 + Track2 CD-DA, ISO 파일 63개로 이름이 같다(`docs/survey/disc{1,2,3}_files.txt`).
- `MES.ARC`(대사) md5 `61cc20a5…`는 3장이 같다. 번역은 한 벌로 3장에 쓴다.
- `0.BIN`(실행 파일, 적재 0x06004000)은 장마다 다르다(md5 ee2c21e6… / 79af2581… / c80fd238…). 실행 파일을 고치면 3벌을 따로 고쳐야 한다.
- `CDDA.PCM`의 ISO 항목은 데이터 트랙 밖(오디오 트랙)을 가리킨다. 추출기는 이 파일을 건너뛴다.

## 대사 — MES.ARC

- 2048바이트 단위로 `elfpak` 600개가 이어져 있고, 파일 안에는 목차가 없다.
- elfpak = `"elfpak\x1a\0"` + u32LE «압축 본문 크기»(원래 크기가 아님) + Okumura LZSS(링 4096, 시작 0xFEE, 0으로 채움, 12비트 위치 + 4비트 길이(+3), 플래그는 LSB부터). 600개 모두 입력을 정확히 다 쓰고 풀린다 → `tools/elfpak.py`. 풀린 파일은 `work/disc1/mes/NNN.bin`이고 합계 14.4 MB다.
- 풀린 파일 하나 = 장면 하나. SJIS 대사 + **SH-2 코드**(장면 오버레이, 0x060A0000 근처에 실린다)가 함께 들어 있다.
  - 대사 꼴: `［이름］：본문`, 주인공 이름 자리 = `00 00`, 줄 구분 = `00 00 00 09` 등. 제어 코드 의미는 아직 모른다.
  - 코드가 대사 위치를 어떻게 가리키는지(절대 주소인지 상대 위치인지)는 아직 모른다. 길이를 바꿔 재배치할 수 있는지가 **최대 미확정 위험**이다.
- 실행 파일에 `01M.MES`·`02C.MES`… 이름이 610개(고유 610개) 있다. ARC 칸은 600개라서 이름↔칸 대응표 위치는 아직 못 찾았다.
- 분량(1차 추정): 가나가 든 고유 문자열 약 50,000개, **약 121만 자**(중복 포함 전체 약 205만 자). 텍스트가 든 장면은 500개다.

## 기타 텍스트

- `VOI.ARC`(2.5 MB, 압축 없음): `h001`·`k001` 같은 음성 ID + 대사. 고유 11,560줄 중 MES에 없는 것은 30줄뿐이다(문자열 조각). 음성이 붙은 대사 사본으로 보이며 용도는 아직 모른다 — MES와 같은 번역을 써야 한다.
- `0.BIN` 평문: 제목 메뉴(下級生を途中からする…), 저장·불러오기(データなし, カートリッジＲＡＭを使う, やっぱりやめる), 이름 입력 글자판(かきくけこ…, かな·消す 등).
- 장면 메뉴(チャイムを鳴らす, 世間話をする, 誰かに電話をしちゃう …)는 MES 안에 있다.
- 그림 글자 후보: 제목 로고, 이름 입력 머리 「主人公の名前を入力してください」(문자열 검색 0건), 날짜·시각·돈 HUD, 이름 입력 버튼 「カナ」「決定」(0.BIN에 없음).
- 아직 안 본 것: NAME.DAT, *.ACM(CNAME/KNAME/BNAME/OPTION), OMAKE.DAT, STAFF.DAT(⛔스태프 롤은 허락 없이 손대지 않는다), ANM.ARC·GP8.ARC(elfpak 355/846개 — 그림으로 추정).

## 글꼴

- `SJIS2.KNJ` = 14×14, **1바이트/화소**(값 0x88 = 바탕, 니블 조합 = 안티 단계), 글자당 196 B, **2,060칸**(+꼬리 28 B). 게임에 쓰이는 글자만 JIS 순서로 모았다.
- 대응표: 0.BIN 0x06060508(파일 0x5C508)에 SJIS 전 영역 u16 표가 있다. 색인 = (선행−0x81 또는 −0xC1)×188 + (후행−0x40 또는 −0x41), 값−1 = 글꼴 칸. 0이면 글자 없음(0xFFFF 처리). 조회 함수는 0x06015F90, 그리는 곳은 0x06016040(칸×0xC4).
- 실행 중 위치: LowRAM 0x00280000(스테이트 3장에서 파일과 같음). 0x00270000~0x0027FFFF는 세 스테이트 모두 비어 있지만, 칸이 충분하다고 사용자가 판단해서 늘리지 않는다.
- 반각 `ANK.FNT`(2,660 B)는 따로 있다.
- 한글 방침(안): SJIS 코드 공간을 그대로 쓰고 대응표 + 글꼴 칸만 다시 쓴다 → 렌더러 코드는 고치지 않는다. 대응표·글꼴 그리기 경로가 여럿(0x280000 참조 15곳)이라 메뉴·이름 입력 경로를 따로 확인해야 한다.

## 다시 넣기 판정 (2026-10-23)

- **대사 참조**: 장면 파일은 RAM `0x060A0000` 에 그대로 실린다(스테이트 3 = 576번, 5,912 B 일치). 대사 조각 93,294개 **전부**가 장면 파일 안 32비트 절대 주소(리터럴 풀)로 참조된다(129,396곳). → 조각을 옮기고 늘리려면 이 주소만 고치면 된다.
- **증가량(추정)**: 번역 후 텍스트 바이트 +3.9%. 최대 장면 159번 0x1D4B4 → +168 B 정도. 스테이트 3장 모두 적재 주소 뒤 RAM 은 비어 있음 — 실제 버퍼 한계는 미확정(159번 장면에서 스테이트 확인 필요).
- **파일 위치표**: 0.BIN 파일 오프셋 0x4B918~0x4DB2C, 12 B 레코드 727개 = (이름 문자열 주소 u32BE, 시작 섹터 u32BE, 크기 u32BE). `.MES` 600개는 섹터 = MES.ARC 묶음 위치(2048 단위), 크기 = 압축 본문 + 12(elfpak 머리) 로 600/600 일치. 0.BIN 은 장마다 달라 3장 각각 고친다(오프셋은 장마다 다시 찾을 것).
- **다시 넣기 설계(안)**: 장면마다 ① 원래 자리에 들어가는 조각은 제자리, 넘치는 조각은 파일 끝에 덧붙이고 리터럴 주소 갱신 ② 같은 문자열 공유로 크기 절약 ③ LZSS 재압축(게임 해제기 규칙) ④ MES.ARC 재배치 + 3장의 0.BIN 위치표(섹터·크기) 갱신 ⑤ ARC 가 커지면 ISO 디렉터리·파일 배치 처리.
